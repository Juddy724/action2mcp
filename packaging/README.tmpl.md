# Action2MCP：把浏览器里的业务操作录成 AI 能调用的工具

在浏览器里正常点一遍业务流程（比如“查询客户”），Action2MCP 会把背后的接口请求录下来，整理成 **MCP 工具**。之后 Claude、Cursor、Codex 等 AI 就能直接调用这些工具。

- **免安装**：解压后双击启动脚本即可，所有数据都保存在程序旁边的 `data` 文件夹里。
- **一句话开始录制，一键结束**。
- **登录态和工具分开保存**：工具里不存 Cookie 或 Token，调用时自动带上你在专用浏览器里的登录状态；导出的文件也不含任何登录信息。
- **流程包开关**：按工作场景把工具分组，只有开启的流程包里的工具才会被 AI 看到。
- **工具审批**：在工具编辑页的「审批模式」选择不审批（off）或每次都审批（always），写入工具默认每次都审批。WebSocket SQL 控制台的审批模式可在中间件里配置为每次审批（默认）或关闭；关闭后守卫仍然生效。AI 调用时，控制台会出现待审批卡片；等待超时可在「接入 AI / 设置」调整。
- **WebSocket SQL 控制台**（0.5.5 / 0.5.7 / 0.5.8 / 0.5.9 / 0.5.10 / 0.5.11）：在「中间件管理」里把数据平台的 SQL 查询登记为 WebSocket 中间件（模式选「SQL 控制台」），AI 通过 `ws_sql_query` 按数据源别名查询。只读 SELECT、显式 LIMIT、EXPLAIN 预检、200 行封顶，令牌从本机收获的请求头注入。0.5.4 的护栏 `WS` 工具会在启动时自动迁移过来。0.5.7 起每个数据源按「数据源 ID + envId + envType」三个值确定一个库，envType 默认为 PROD。0.5.8 起 `{{header.cookie}}` 从登录中心的 Cookie 罐取值，不再当作需要单独收获的自定义请求头。0.5.9 起审批记录的执行结果可点「查看全部」看完整返回，并修正了过短的 Cookie 或数据源 ID 把查询结果误遮成 `******` 的问题。0.5.10 起 SQL 控制台的审批模式可配置为每次审批（默认）或关闭；关闭后只读/LIMIT/索引等守卫仍生效。审批记录表格改为顶端对齐。0.5.11 起修复了页面较长、Cookie 等密钥较多时，返回给 AI 的结果整段被换成 `******` 的问题；密钥（含各种编码形式）仍会遮掉，但不再因扫描量超限而把整页打码。0.5.12 起，HTML 结果默认清洗成 Markdown，业务失败会标成工具错误，写操作工具会在说明里标注；这些均可在工具编辑页配置，AI 不能修改。
- **登录中心修复**（0.5.6）：从 WebSocket 中间件生成登录配置时使用对应的 http(s) 网站地址（`wss://` → `https://`，`ws://` → `http://`）；已登录会立即判定成功，必要时刷新页面以收获请求头；等待登录有 5 分钟超时，可点「取消」，关闭窗口也会结束等待。
- **阶梯式获取工具**（0.4.0 新增）：AI 连上后先只看到一份流程包列表，按当前任务加载需要的包，再拿到包里的工具。不相关的工具不会塞进 AI 的上下文。
- **登录过期自动重新登录**（0.2.0 新增）：AI 调用时发现登录过期，会在后台自动用企业微信或保存好的账号密码重新登录，然后重试，AI 无感知。
- **配置管理**（0.2.0 新增）：加密保存账号、密码等配置值，工具里用 `{{secret.名称}}` 引用，**AI 看不到真实的值**。
- **中间件管理**（0.3.0 新增）：添加 MySQL / OceanBase、Redis、RocketMQ / Kafka / RabbitMQ、WebSocket（终端或 SQL 控制台），加进流程包后 AI 就能查库、读写缓存、收发消息、在远端终端查日志，或按数据源别名执行受护栏约束的 SQL。每个中间件的增、删、改、查等权限可以单独开关，**默认只读**。密码同样加密保存，AI 看不到。WebSocket 不保存密码，调用时用「登录中心」里该网站的登录状态；SQL 控制台还会注入本机已收获的请求头令牌。

## 1. 启动

| 系统 | 操作 |
|---|---|
{{START_ROWS}}

启动后浏览器会自动打开控制台 **http://localhost:7788**。如果没有自动打开，请手动访问这个地址。

> 需要电脑上已经安装 **Google Chrome** 或 **Microsoft Edge**。录制时会打开一个**专用的浏览器窗口**（独立的配置，和你平时用的浏览器互不影响）。

## 2. 录制（三选一）

**方式 A：控制台**：在「录制」页填写名称和网址，然后点「开始录制」。

**方式 B：命令行**（在程序所在文件夹里打开终端）：

```
{{CLI}} rec 查询客户 https://你的系统网址
```

专用浏览器打开后，像平时一样登录并操作一遍。页面右下角会显示红色的「● 录制中」浮条。

**结束录制**（三选一）：
- 点击页面右下角的「结束录制」按钮
- 执行 `{{CLI}} stop`
- 直接关闭这个浏览器窗口

## 3. 保存为工具

1. 在控制台打开刚才的录制。业务请求排在最上面，静态资源、埋点、配置类等噪音请求会自动折叠。
2. 选中真正有用的那个请求（例如 `/api/customer/search`），点「保存为工具」。
3. 勾选哪些字段要作为 AI 可以填写的参数（例如 `keyword`），写一句工具说明，然后选择或新建一个流程包。保存即可。

请求里的 Cookie、Authorization、CSRF 等登录相关请求头会被**自动剔除**，调用时再从专用浏览器的登录态中实时补上。

### 让 AI 分析一次录制

录完之后，可以对已经接好的 AI 说：

> 帮我把录制记录里的「线上问题排查」识别一下，并保存成工具。

AI 使用内置流程包「录制分析」（不是普通流程包，控制台流程包列表里没有这一条）。阶梯模式下它会出现在 `list_packs` 里，加载后再调用；平铺模式下 `rec_*` 工具直接出现在工具列表里。默认开启，可在「接入 AI / 设置」里关闭「让 AI 分析录制」。关闭后这些工具不再出现，调用也会失败。

AI 会按这个顺序做：

1. `rec_list_recordings`：看有哪些录制。起始网址只给出源，例如 `https://app.example.com`，不含路径和查询参数。
2. `rec_get_recording`：看这条录制的全貌。相同接口会合并，查询参数只给名字。
3. 必要时 `rec_get_request`：看单条请求的脱敏详情。Cookie、Authorization、Token、密码和配置管理里的密钥都不会给 AI。
4. `rec_annotate`：给业务相关的请求写一句作用说明。会修改数据的请求标成 `write`，并告诉你。
5. 选出完成这个流程真正需要的最少请求。如果你没有说保存到哪个流程包，AI 必须先问你（可以先用 `rec_list_target_packs` 列出已有流程包）。不要让它自己猜，也不要让它随便新建一个包。
6. `rec_save_tool`：按你指定的流程包保存工具。只有你明确说出一个新的流程包名称时，才会新建。

## 4. 流程包

在「流程包」页用开关控制哪些工具对 AI 可见。每个流程包里只显示已经加进来的工具：点「+ 添加工具」，在弹出的列表里搜索、勾选，点「确定」即可加入；点工具右边的「×」把它移出流程包（工具本身不会删除）。中间件也一样，用「+ 添加中间件」和「×」。保存录制的工具时也可以直接勾选放进哪个流程包，不选就先不加入任何流程包。

**关闭的流程包 AI 完全看不到，也调用不了。** 给每个流程包写好「说明」和「适用场景」（例如“记工时、查我的任务”），AI 会据此判断该加载哪个包。

每个包还可以写一份「使用说明」（Markdown，最长 8KB）。这里写工具的调用顺序、上一步的哪个字段填下一步、失败时怎么办。阶梯模式下，AI 加载这个包时会在返回结果的 `guide` 里看到全文，并被要求先按说明调用。平铺模式下，已开启流程包的使用说明写在连接时的说明里，修改后需要重新连接 MCP。选包用的列表里不包含这份全文。使用说明只告诉 AI 怎么用，不能代替流程包开关和中间件权限。不要在里面写密码、Cookie 或密钥；导出时，配置管理里已有的密文会被替换成 `******`。

### AI 获取工具的方式：阶梯模式 / 平铺模式

在「流程包」页最上面可以切换，默认是**阶梯模式**。

**阶梯模式（默认，推荐）**：AI 连上后只看到 4 个入口工具：

| 入口工具 | 作用 |
|---|---|
| `list_packs` | 第一步：列出已开启的流程包（id、名称、说明、适用场景、工具数、工具名、包含的中间件、本次会话是否已加载） |
| `load_pack` | 第二步：按名称或 id 加载一个流程包。返回里有使用说明 `guide`（为空表示没写）以及工具的名称、说明和参数格式。`guide` 有内容时先按它调用。工具会加入 AI 的工具列表（服务器会发出标准的 `notifications/tools/list_changed` 通知） |
| `unload_pack` | 用完卸载，不填则卸载全部 |
| `call_pack_tool` | 兜底：有些 AI 客户端收到通知后不会刷新工具列表，这时按工具名 + 参数调用包内工具 |

几点说明：

- 加载状态按**连接**（MCP 会话）保存：每个 AI 客户端、每个 `{{CLI}} mcp` 进程各自独立，互不影响。Action2MCP 重启后需要重新加载。
- **宽松调用**：只要工具所在的流程包是开启的，即使本次没有 `load_pack`，直接按工具名调用或通过 `call_pack_tool` 调用也都可以。真正控制权限的是控制台里的开关；加载只是为了少占 AI 的上下文。调用关闭的流程包里的工具会返回“不存在或所在流程包未开启”，并提示先 `list_packs`、`load_pack`。
- 自动重新登录、配置值遮盖（AI 看不到密码）、中间件权限（返回「无权限」）、操作日志等规则，无论直接调用还是通过 `call_pack_tool` 调用都完全一样。
- 在控制台开关流程包、修改工具或切换模式时，会实时通知已连接的 AI 客户端刷新工具列表（客户端需要支持该通知）。
- 工具名 `list_packs`、`load_pack`、`unload_pack`、`call_pack_tool`，以及 `rec_list_recordings`、`rec_get_recording`、`rec_get_request`、`rec_annotate`、`rec_list_target_packs`、`rec_save_tool` 被保留，录制的工具不能用这些名字。
- 内置流程包「录制分析」不占流程包列表里的一条记录，默认开启，在「接入 AI / 设置」里关闭。它用来让 AI 阅读录制、标注接口作用并保存工具，见上一节。

**平铺模式**：和 0.3.0 一样，AI 一连上就看到所有已开启流程包里的全部工具。工具很少，或者客户端不支持动态工具列表时可以切回这个模式。

## 5. 接入 AI

先让 Action2MCP 处于运行状态（双击启动脚本，或执行 `{{CLI}}`）。

**Cursor**（`~/.cursor/mcp.json`）：

```json
{
  "mcpServers": {
    "action2mcp": { "url": "http://localhost:7788/mcp" }
  }
}
```

**Claude Desktop**（设置 → 开发者 → 编辑配置，即 `claude_desktop_config.json`）。Claude Desktop 用命令行方式启动，路径请换成你解压的实际位置：

```json
{
  "mcpServers": {
    "action2mcp": {
      "command": "{{EXAMPLE_PATH}}",
      "args": ["mcp"]
    }
  }
}
```

**Codex**（`~/.codex/config.toml`）：

```toml
[mcp_servers.action2mcp]
command = "{{EXAMPLE_PATH_TOML}}"
args = ["mcp"]
```

**Claude Code**：

```
claude mcp add --transport http action2mcp http://localhost:7788/mcp
```

控制台「接入 AI / 设置」页里有填好本机真实路径的配置，可以直接复制。

### 工具审批的范围与限制

在工具编辑页的「审批模式」设为每次都审批后，AI 调用会先在控制台显示待审批卡片。核对请求预览后，可以通过、修改参数后通过，或拒绝并告诉 AI 原因；等待超时可在「接入 AI / 设置」调整。

- 审批只约束通过 MCP 发起的 AI 调用；能直接访问 localhost HTTP 的客户端仍可伪造请求，审批不能代替本机访问权限管理。
- 请求已经发出后无法撤回。
- MCP 会话 DELETE 和 stdio 桥退出不保证取消待审批调用；这类调用会继续等待用户拒绝或超时。
- 大整数精度与现有 MCP JSON 的 float64 解码路径一致，超过其精确表示范围的整数可能丢失精度。
- 参数按整体替换，未提交的参数保留原值；非秘密参数原样展示、原样替换，不解析或重写内部 JSON/form。秘密参数整体遮罩；未改动的 ****** 保留原值，输入完整新值则替换整个参数；提交值内部夹带 ****** 则 400，未执行。


### WebSocket SQL 控制台（0.5.5，数据源三元组见 0.5.7）

数据平台这类「一条 WebSocket 消息执行 SQL」的能力，放在「中间件管理」里，和 Phoenix 终端一样是 WebSocket 中间件，只是模式选「SQL 控制台」。加入已开启的流程包后，AI 会看到通用工具 `ws_sql_query`（参数是中间件名、数据源别名、SQL），与直接连库的 `db_query` 不是同一个工具。

升级到 0.5.5 时，若本地还有 0.5.4 那样带 SQL 护栏的 `WS` 工具，启动时会自动转成 SQL 控制台中间件（例如 `demo_sql_query` 会变成中间件 `demo_sql`），并把它从所属流程包里改挂到新中间件上，原工具删除。迁移是事务性的、可重复执行。也可在「工具」页对尚未迁移的护栏工具点「转为 SQL 控制台」。

- 审批模式可在中间件编辑页配置为「每次审批」（always，默认）或「关闭」（off）。新的和升级过来的中间件都是每次审批。关闭后 AI 可直接执行查询，不必再等批准，但只读 SELECT、显式 LIMIT、函数白名单、EXPLAIN 全表扫描拒绝、200 行封顶这些守卫仍然生效。审批模式只能在控制台改，不会出现在 MCP 工具说明里，AI 不能查看或修改。审批预览只显示中间件名、数据源别名和即将执行的 SQL，不会出现数据源 ID、环境参数或登录令牌；批准前不会向目标发送业务消息。
- 只允许单条只读 SELECT（含 WITH），必须带显式 `LIMIT`（最多 200 行）。执行前会另开连接做 `EXPLAIN` 索引预检；预检失败或护栏拒绝时不会发送业务 SQL。结果若超过上限会截断并注明。
- 登录令牌不要写进配置。调用时从本机已收获的自定义请求头注入，例如 `{{header.sso-epctoken}}`（不会误用同名 Cookie）。若尚未收获到令牌，测试连接和调用都会失败，不会发出 SQL。「测试连接」只做握手，不会执行任何用户 SQL。
- `EXPLAIN` 只是执行前预检，不保证第二次连接的实际计划与预检完全一致，也不提供远端只读事务。

**配置数据源：** 在中间件表单里按行填写「名称」「数据源 ID」「envId」「envType」「说明（给 AI 看）」，可添加 / 删除。名称是 AI 使用的别名；说明会出现在 `ws_sql_query` 的工具描述里，方便 AI 根据用户的问题自己选库。一个库由「数据源 ID + envId + envType」三个值一起确定。envType 默认为 PROD，也可以改成其他值。这些标识以及 spaceCode、dbType 只保存在本机，不会出现在工具说明、审批预览或审计里。spaceCode 和 dbType 在中间件级填写默认值；某一行需要不同值时，再点该行「高级」覆盖。

要添加或核对这些值：在数据平台的 SQL 控制台对该库执行一次查询并录制，然后从录到的 `execute` 消息里复制 `dsId`、`envId`、`envType`。同一个站点上有多套库时，再点「添加」补一行即可。保存后，已连接的 AI 客户端会收到工具列表变更通知，`tools/list` 立即反映当前的别名和说明。

升级到 0.5.7 时，若本地还有 0.5.5 / 0.5.6 把 envId / envType 写在中间件默认环境参数里的配置，启动时会把这两个值拷到每一行数据源上，并去掉旧的默认字段；迁移是事务性的、可重复执行。

升级到 0.5.8 时，`{{header.cookie}}` 改为从登录中心该网站的 Cookie 罐取值。测试连接和调用在罐里没有对应 Cookie 时会提示缺少 Cookie，而不会报「站点缺少请求头 cookie」。Cookie 值不会出现在工具说明、审批预览、审计或报错里。已迁过来的 Cookie 绑定会被规范化为 `{{header.cookie}}`。

升级到 0.5.9 时：审批记录里的执行结果默认只显示前面大约 20 行或 2KB，可点「查看全部」滚动查看完整结果并复制（按 AI 看到的同样规则脱敏后保存，最长 1MB）。过短的 Cookie 值或数据源配置标识不再从成功的结果行里按子串替换，避免把普通数字、「LIMIT 10」误遮成 `******`；这些标识仍然不会出现在工具说明、审批预览、审计和报错里。

升级到 0.5.10 时：SQL 控制台中间件增加可配置的审批模式（每次审批 / 关闭，默认每次审批；已有中间件保持每次审批）。关闭后调用不再弹出审批，审计会记下「未审批，直接执行」，守卫、脱敏和安全拨号不变。审批模式只能在控制台修改，不会出现在 MCP 工具说明里。审批记录表格的单元格改为顶端对齐，使「最终参数」和「执行结果」的代码块从同一行开始。

升级到 0.5.11 时：修复了工具结果（例如较长的 HTML 页面）在 Cookie 等密钥较多时整段被脱敏成 `******` 的问题。密钥以及它们的 URL、HTML、Base64、JSON 编码形式仍会被遮掉；超过体积或解码深度上限时仍然整段封闭。脱敏改为按解码视图一次扫描全部变体，计算量不再随密钥数量成倍增加。

升级到 0.5.12 时：HTML 工具结果默认会去掉脚本和导航并转成 Markdown（可在工具编辑页改回原始 HTML 或只取某个区域）；JSON 保持原样。页面上的错误提示和明确的 JSON 失败会标成工具错误。写操作工具的 MCP 说明前面会加上「【写操作，仅在用户明确要求时调用】」。已有工具自动使用这些默认行为，不必改配置。密钥脱敏仍然覆盖最终交给 AI 的全部文字。


### 登录中心（0.5.6）

从 WebSocket 中间件（终端或 SQL 控制台）自动创建登录配置时，网站地址使用对应的 http(s) 源（`wss://` → `https://`，`ws://` → `http://`），不再把 `wss://` 填进登录中心。登录入口、登录页和检测地址必须是 `http://` 或 `https://`。

「测试重新登录 / 打开浏览器登录」时，如果浏览器里已经处于登录状态，会马上判定成功并关闭窗口；若还缺必要请求头（例如 `sso-epctoken`），会刷新或再次打开该网站以捕获请求头，全部收获后才算成功。等待登录最多 5 分钟，超时会结束并显示失败原因；等待过程中可以点「取消」，关闭弹出的窗口也会结束等待。


## 6. 登录过期怎么办：登录中心（自动重新登录）

保存工具时，程序会自动为这个网站建一条**登录配置**，在控制台「登录中心」页可以看到和修改。AI 调用工具时，如果发现登录已过期，会在后台自动重新登录，再重试一次。成功时，结果开头会多一行“（登录已过期，已自动重新登录并重试）”。

### 录制时自动识别企业微信登录（0.4.2 新增）

在录制浏览器里用企业微信扫码登录后，结束录制会自动把业务网站加入「登录中心」，并收集 OAuth / SSO 跳转中的中间登录主机。入口地址保留起始网址的域名和路径，去掉查询参数与 `#` 后的路由；生成的配置不复制 Cookie、Token 或 OAuth code。企业微信静态图片、脚本等资源不会触发识别。

已有企业微信登录配置时只合并单点登录地址；已有账号密码或手动登录配置时会提示建议，保留原配置。旧录制也可以在详情页点击「加入登录中心」重新识别。自动识别后可在「登录中心」调整登录入口，并点击「测试重新登录」验证。

**怎么判断“登录过期”**（默认全开，一般不用改）：

- 接口返回 401 / 403；
- 被重定向到登录页（网址里含 login、sso、passport、cas、oauth 等）；
- 本该返回数据的接口返回了一个登录页面，或者一段“跳转到登录页”的脚本（比如禅道）；
- 返回内容里有你在「登录中心」填的关键字（例如 `"code":10001`、`请先登录`）。

**登录方式**（每个网站选一种）：

| 方式 | 适合 | 说明 |
|---|---|---|
| 企业微信 / 单点登录（默认） | 支持企业微信扫码 / 一键登录的系统 | 在后台打开网站的登录入口，利用专用浏览器里已有的企业微信登录状态自动走完登录。登录页上如果有“企业微信登录”按钮，或企业微信的“快速登录”按钮，会自动点击。 |
| 账号密码 | 不支持企业微信的系统 | 使用「配置管理」里保存的账号密码自动登录。可以选「重放录制的登录请求」（最快，会自动取新的 CSRF），也可以选「在浏览器里自动填表」。 |
| 手动登录 | 有验证码、短信的系统 | 过期时直接弹出浏览器窗口，提示你手动登录。 |

**企业微信本身的登录也过期了怎么办？** AI 会收到提示“企业微信登录已过期，请在弹出的窗口扫码后重试”，同时电脑上会弹出浏览器窗口。用手机企业微信扫码确认后，窗口会自动关闭，再让 AI 重试即可。多个网站同时过期时，只会弹出一个窗口。

其他说明：

- 同一个网站同时有多个调用过期时，只会重新登录**一次**，其余调用会等它完成后一起重试。
- 账号密码登录如果被网站拒绝（例如密码已修改），会提示“网站提示「用户名或密码错误」”，并在 10 分钟内不再重试，避免账号被锁。在「配置管理」里改好密码后会立即恢复。
- 「登录中心」可以对每个网站点「测试重新登录」或「打开浏览器登录」，并查看最近的登录状态和失败原因。如果公司 SSO 不是企业微信自带的地址，可以在「单点登录地址」里填上（例如 sso.company.com）。
- 可选的**定时保活**（默认关闭）：按设定的分钟数在后台检查一次登录状态，过期就提前重新登录。
- 也可以随时在控制台点「打开浏览器登录」（或执行 `{{CLI}} login https://你的系统网址`）手动登录一次。

## 7. 配置管理（账号密码等，AI 不可见）

在控制台「配置管理」页添加配置值，每一项都有：

- **名称**：只能用英文字母、数字、下划线，例如 `oa_user`、`oa_pass`；
- **类型**：「密码」（secret，显示为 ******）或「普通」（cfg，例如用户名、部门编号）；
- **所属网站**（可选）和备注。

**使用方法**：

- 在工具的地址、请求头、请求体里写 `{{secret.oa_pass}}` 或 `{{cfg.oa_user}}`，调用时在本机替换成真实的值。
- 在「登录中心」把某个网站的登录方式设为「账号密码」，然后选择账号和密码分别对应哪一项配置。
- **录制时直接保存**：录一遍登录操作（输入账号密码、点登录），在录制详情里选中被标为「登录请求」的那条请求，点「保存为登录配置」。账号和密码会加密存进配置管理，这个网站的登录方式会自动改为「账号密码」+「重放录制的登录请求」。录制记录里的密码会同时被抹掉。
- **保存工具时**，如果请求里出现了已保存的配置值（例如固定的 API Key），会提示改成 `{{secret.名称}}` 引用。

**安全说明**：

- 所有值都用 AES-256-GCM 加密后保存在 `data/a2m.db`，密钥是 `data/secret.key`（首次启动时自动生成）。**这两个文件要一起备份；丢了 secret.key，已保存的值就无法解密，需要重新填写。**
- AI 只能看到工具参数，看不到任何配置值。**「密码」类型**的值就算被网站原样返回，在调用结果、错误信息和日志里也会被替换成 ******。「普通」类型不做遮盖，用户名等不敏感的值可以用它，**凡是敏感的值都请选「密码」**。
- 在控制台查看明文（「显示」按钮）只允许本机访问。
- 导出文件里只有配置的**名称**，没有值。同事导入后，会在配置管理里看到“（待填写）”的项目，填上自己的账号密码即可使用。

## 8. 中间件管理（数据库、Redis、消息队列、WebSocket）

在控制台「中间件」页点对应的添加按钮，填写连接信息，然后点「测试连接」确认能连通，最后保存。

| 类型 | 需要填写 | 说明 |
|---|---|---|
| MySQL / OceanBase | 地址、端口、用户名、密码、默认库 | OceanBase 请使用 **MySQL 模式**的租户，用户名按 OB 的格式填（例如 `user@tenant#cluster`） |
| Redis | 地址、端口、密码（可选，ACL 用户名也可填）、库编号（db，默认 0）、TLS | 也支持集群和哨兵模式（见下方限制） |
| 消息队列 | 种类（RocketMQ / Kafka / RabbitMQ）+ 对应地址 | RocketMQ 填 NameServer 地址；Kafka 填 broker 地址，可用逗号分隔多个；RabbitMQ 填地址、端口、用户、密码和 vhost |
| WebSocket | 地址（`ws://` 或 `wss://`）、发送的文本帧 | 用来连一个远端终端。地址和帧里用 `{{参数名}}`，`{{command}}` 会换成要执行的命令。认证用「登录中心」里这个网站的 Cookie |

**密码不会以明文保存**：在表单里填写的密码，会自动加密存进「配置管理」（名称类似 `mw_1a2b3c4d_password`）。中间件本身只记录这个名称。编辑时如果密码框留空，就沿用原来的密码。删除中间件时，这条密码也会一起删除。

**加进流程包**：在「流程包」页，每个流程包下面都有中间件的勾选框。勾选后，**开启这个流程包时**，AI 会看到下面这些通用工具（每个工具都需要传入中间件名称）。关闭流程包后，这些工具和中间件对 AI 都不可见：

| 工具 | 作用 |
|---|---|
| `db_query` | 执行一条 SQL（可用 `?` 占位符传参数） |
| `db_list_tables` / `db_describe_table` | 列出表、查看表结构 |
| `redis_command` | 执行一条 Redis 命令，例如 `GET user:1` |
| `redis_scan` | 按通配符查找 key（代替 KEYS） |
| `mq_list_topics` | 列出 Topic |
| `mq_peek` | 查看最近的几条消息（**不会提交消费位点**，不影响业务消费者） |
| `mq_send` | 发送消息（可带 key 和 tag） |
| `mq_create_topic` | 创建 Topic / 队列 |
| `pod_read_log` | 在 WebSocket 终端里查看日志末尾（只执行 `tail`） |
| `pod_exec` | 在 WebSocket 终端里执行一条命令（默认关闭） |

AI 在工具说明里只能看到中间件的**名称、类型、你写的说明和已开启的权限**，看不到地址、账号和密码。WebSocket 的地址同样不会出现在工具说明里。调用时要在参数 `middleware` 里传入你填的那条连接的名称。

### 权限开关

每个中间件都可以单独开关下面这些权限。新建时默认**只开启第一项（只读）**：

| 类型 | 权限 | 对应的操作 |
|---|---|---|
| 数据库 | **查**（默认开） | SELECT / SHOW / DESCRIBE / EXPLAIN |
| | 增 | INSERT / REPLACE |
| | 改 | UPDATE、SELECT … FOR UPDATE、INSERT … ON DUPLICATE KEY UPDATE |
| | 删 | DELETE / TRUNCATE |
| | DDL | CREATE / ALTER / DROP 表、索引、视图 |
| Redis | **读**（默认开） | GET / HGETALL / LRANGE / SCAN 等 |
| | 写 | SET / HSET / LPUSH / EXPIRE 等 |
| | 删 | DEL / HDEL / LPOP / SREM 等 |
| | 脚本 | EVAL / EVALSHA（脚本能访问任意 key，请谨慎开启） |
| 消息队列 | **查看消息**（默认开） | 列出 Topic、查看最近的消息 |
| | 发送 | 发送消息 |
| | 管理 | 创建 Topic / 队列 |
| WebSocket | **查日志**（默认开） | `pod_read_log`，只执行 `tail` |
| | 执行命令 | `pod_exec`。可再填「允许的命令」（如 `tail`、`ls`、`grep`）；留空则不限制。管道可用，但每一段都要在列表里。不能用重定向或命令替换绕过列表。`find` 只允许 `-name`、`-mmin`、`-mtime`、`-type`、`-size`、`-maxdepth`；`cut` 只允许 `-c`；`rg` 不能带 `--pre` |

AI 执行了未开启的操作时，会收到错误：**`无权限：中间件「订单库」未开启「删」权限`**。权限修改后**立即生效**，不需要重启，也不需要重连 MCP。

**范围限制**（可选，留空表示不限制）：

- 数据库：**允许的库**、**允许的表**（例如 `orders, order_items`）。SQL 里引用的每一张表（包括 JOIN、子查询）都会检查。
- Redis：**允许的 key 前缀**（例如 `user:, session:`）。`redis_scan` 也只能查找这些前缀下的 key。
- 消息队列：**允许的 Topic**（支持 `order_*` 这样的通配符）。
- WebSocket：**允许的命令**（只约束 `pod_exec`）。`pod_read_log` 始终是 `tail`，不受这份列表影响。

**其他保护**（都在服务端执行，AI 无法绕过）：

- SQL 用 MySQL 语法解析器逐条分析，**一次只允许一条语句**。解析不了的 SQL 一律拒绝。查询（SELECT、SHOW 等，FOR UPDATE 除外）一定在**只读事务**里执行，即使调用了会写数据的存储函数也写不进去。
- 不带 WHERE 的 UPDATE / DELETE 默认拒绝（可以在中间件里关闭这一项）。TRUNCATE 需要「删」权限。
- 始终禁止：读写文件（`INTO OUTFILE`、`LOAD_FILE`、`LOAD DATA`）、`GRANT`、`SET GLOBAL`、存储过程 `CALL`、`LOCK TABLES`、`SLEEP`，以及访问 `mysql` 系统库（里面有账号和密码哈希）。
- Redis 始终禁止：`FLUSHALL`/`FLUSHDB`、`CONFIG`、`KEYS`、`SHUTDOWN`、`DEBUG`、`SELECT`（切换库）、`MIGRATE` 等运维命令。
- 结果自动限制：查询没写 LIMIT 时自动加上（默认 200 行），返回内容超过上限（默认 256 KB）会截断并提示。每次调用有超时（默认 15 秒）。这三个值都可以在中间件里修改。
- 每次调用（包括被拒绝的）都会记进「中间件」页底部的**操作记录**：时间、AI 客户端、中间件、执行的语句或命令、需要的权限、结果和耗时。

### 导出 / 导入

导出文件里**包含**中间件的连接信息（地址、端口、用户名）、权限和流程包关系，**不包含**密码。同事导入后，密码会显示为“（待填写）”，在「配置管理」里填上即可。没填之前调用会提示“密码还没有填写（待填写）”。

## 9. 分享给同事

- 控制台「设置」页点「导出」，或执行 `{{CLI}} export 我的工具.a2m`。导出的文件**只包含工具定义、流程包、登录配置和中间件连接信息（不含任何 Cookie、账号密码的值）**。
- 同事在他的 Action2MCP 里导入（控制台「导入」，或执行 `{{CLI}} import 我的工具.a2m`），在「配置管理」里填上自己的账号密码（如果有“（待填写）”的项目），再用**他自己的账号**登录一次即可使用。
- **不要**把 `data` 文件夹直接发给别人：里面有你的浏览器登录状态、原始录制记录和加密配置的密钥。

## 11. 目前的限制

- 只自动补 **Cookie 和 CSRF**。如果网站把 Token 存在 localStorage，再放进 `Authorization: Bearer` 请求头，那么录制时的 Token 不会保存进工具，调用时也不会自动补，这类工具大概率会返回 401。如果是**固定不变**的 Token / API Key，可以存进「配置管理」，在请求头里写 `Bearer {{secret.名称}}`。
- **企业微信扫码无法自动化**：企业微信本身的登录过期后，必须由人在弹出的窗口里扫码一次。如果公司的企业微信 SSO 要求每次都扫码，那么每次过期都会弹窗。
- 不支持带**图形验证码、短信验证码、滑块**的登录，这类网站请把登录方式设为「手动登录」。
- 企业微信登录已失效时，第一次调用需要等约 10 秒才会返回“请扫码”的提示（要先在后台尝试一遍）。
- 「普通」类型的配置值不会被遮盖；配置名称只能用英文字母、数字、下划线。
- 带**签名、时间戳或一次性 nonce** 的接口，重放可能会失败。
- 跨域 iframe 里的请求和 Service Worker 发出的请求暂时录不到。
- 阶梯模式下，部分 AI 客户端收到 `tools/list_changed` 通知后不会刷新工具列表，这时 AI 可以按 `load_pack` 的返回结果用 `call_pack_tool` 调用，功能不受影响。平铺模式下切换流程包后，不支持通知的客户端仍需要手动刷新或重连 MCP。
- 流程包的加载状态只保存在内存里，Action2MCP 重启后 AI 需要重新 `load_pack`（连接本身不会断）。
- 原始录制记录（含请求头）只保存在本机的 `data` 文件夹里。控制台显示时会打码，导出时也不会包含。删除录制即可清除。
- 只监听本机地址（127.0.0.1），并拒绝其他网站发起的跨站请求。
- 同一台电脑上同时运行两份 Action2MCP 时，请在 `data/config.json` 里给其中一份换个端口。
- 中间件相关：
  - 「改」「删」权限下，“必须带 WHERE”只检查有没有 WHERE 条件，不判断条件是否真的有效（例如 `WHERE 1=1` 能通过）。需要更严格的保护，请配合「允许的表」，或者给数据库账号本身只授予需要的权限。**最可靠的做法是给 AI 用一个只读的数据库账号。**
  - Redis 集群 / 哨兵模式、TLS，以及 Kafka 的 SASL 登录已经实现，但还没有在真实的集群环境里测试过。
  - RabbitMQ 无法列出队列（`mq_list_topics` 会提示不支持）。查看消息后，消息会退回队列，但会被标记为“重新投递”（redelivered）。
  - RocketMQ 查看消息需要 2~3 秒。创建 Topic 时需要 broker 地址，默认使用 NameServer 主机的 10911 端口，不对的话请在中间件里填写「Broker 地址」。Topic 列表里会混有集群名、broker 名等系统条目。
  - Kafka 查看消息最长需要约 6 秒。
  - 中间件的地址、端口和用户名在控制台和导出文件里可以看到（AI 看不到）。
